# EPIC: Mark3 Settings Web Interface

> ⚠ Generated without PRODUCT_GRAPH context — graph_bootstrapped: false for starkindustries.

## Goals

1. **Zero-file-editing configuration** — every Mark3 setting (credentials, model routing, agent limits, projects) can be viewed and changed through the UI without manually editing files.
2. **Live credential validation** — all credential changes are validated against live APIs before any file is written, preventing bad state.
3. **Onboarding time reduction** — cut time-to-configured Mark3 instance from 30+ minutes of file editing to under 5 minutes via the UI.

## Objectives

After this EPIC ships, any operator or engineer can fully configure and operate Mark3 through a local browser interface at `http://localhost:3100`. No config file editing is required after initial `setup.sh` runs. The UI covers all four configuration domains (Credentials, Model Routing, Agent Limits, Project Management) plus a read-only view of MCP server settings. Non-technical users can onboard a new Mark3 project without understanding YAML or dotenv syntax.

## Purpose

Mark3 currently requires direct file editing across four distinct config formats: `.env` (credentials), `models.config.yaml` (model routing), `Agents.md` (loop limits), and `projects/*.yaml` (per-project configs). This creates a high barrier for new users, increases the risk of malformed config, and makes credential rotation error-prone. A unified settings UI eliminates these pain points while maintaining the file-system-as-source-of-truth design principle — the UI reads from and writes to the actual files, with no additional database layer.

## High-Level Capabilities

1. Allow the **Mark3 Operator** to view and edit all credentials through a form UI with masked secret fields
2. Enable the **Mark3 Operator** to toggle model routing backend (direct / STARK) and select per-agent models from a dropdown
3. Allow the **Mark3 Operator** to adjust agent loop limits and eval thresholds via sliders without touching `Agents.md`
4. Enable the **Mark3 Operator** to add, edit, and remove project configurations through a structured form (instead of hand-editing YAML)
5. Provide the **Mark3 Engineer** with a read-only diff preview before any config file is written to disk
6. Support the **Mark3 Operator** in validating credentials live (Jira ping, Anthropic ping) before committing changes
7. Allow the **Mark3 Engineer** to inspect the auto-generated `.claude/settings.json` MCP config in a read-only viewer

## Personas Served

| Persona | How They Benefit |
|---|---|
| Mark3 Operator | Configures credentials, model routing, and projects without editing any file manually |
| Mark3 Engineer | Inspects and modifies model routing and agent settings quickly during development |
| New User (Onboarding) | Completes Mark3 setup through a guided UI rather than following multi-file setup instructions |

## Out of Scope

- Multi-user or remote access — this is a single-user localhost tool only
- Authentication / authorization — no login required (localhost-only, single-user)
- Cloud deployment or Docker packaging
- Version history or rollback of config changes (out of scope for v1)
- Direct editing of `.claude/settings.json` (view-only — generated by `setup.sh`)
