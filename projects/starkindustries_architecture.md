## Design Principles

1. **File-system as source of truth** — the UI reads and writes actual files (`.env`, `models.config.yaml`, `Agents.md`, `projects/*.yaml`). No separate database.
2. **Validate before saving** — every credential change is tested live (Jira ping, Anthropic ping) before the file is written.
3. **Non-destructive edits** — always write atomically (write to tmp, rename). Never truncate a config file partially.
4. **Show, don't hide** — display the actual file content alongside the form fields. Power users can see exactly what will be written.
5. **Read-only safe** — opening the UI never modifies any file. All writes are explicit user actions.

## Settings Files Managed

| File | Section | What the UI exposes |
|---|---|---|
| `.env` | Credentials | Atlassian URL/email/token, Anthropic key, graph path, STARK path |
| `models.config.yaml` | Model routing | routing_backend toggle, per-agent model selector |
| `Agents.md` | Loop limits | MAX_LOOPS sliders, eval thresholds |
| `projects/*.yaml` | Project configs | Add/edit/delete projects; Jira key, GitHub repo, code roots |
| `.claude/settings.json` | MCP servers | View only (generated by setup.sh) |

## Module Boundaries

| Module | Responsibility |
|---|---|
| `src/server/routes/config` | REST API: read/write each config file |
| `src/server/lib/validators` | Live validation (Jira ping, Anthropic ping) |
| `src/server/lib/fileio` | Atomic file read/write (YAML, JSON, .env) |
| `src/client/pages` | One page per settings section |
| `src/client/components` | Reusable form fields, status indicators |

## Code Conventions

```
Naming:         camelCase functions, PascalCase components, SCREAMING_SNAKE constants
File structure: feature-first: src/server/routes/{feature}/, src/client/pages/{Feature}Page.tsx
Testing:        co-located: Foo.tsx → Foo.test.tsx
Error handling: Result<T, E> on server; React Query error state on client
No secrets:     never log or return raw credentials — mask after first 4 chars
```

## Test Strategy

```
Unit tests:        src/server/lib/* functions (fileio, validators) — Vitest
Integration tests: API routes against real Mark3 config files — Vitest + supertest
E2E:               none initially — local tool, happy path only
Coverage target:   80%
```
