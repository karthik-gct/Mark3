# Mark3 — Getting Started

## Prerequisites

| Requirement | Notes |
|---|---|
| [Claude Code](https://claude.ai/code) | The coding harness — install the CLI or use the desktop app |
| [Node.js 20+](https://nodejs.org) | For mcp-atlassian and element35-mcp |
| [Jira Cloud account](https://www.atlassian.com/software/jira) | Free tier works |
| [Anthropic API key](https://console.anthropic.com) | For agent model calls |
| element35-mcp (optional) | Context graph — see note below |

> **element35-mcp** is the context graph server (AIHarness_Mark1). Agents work without it (degraded mode — no codebase grounding), but design quality drops significantly. See `context/graph_bootstrap_gap.md`.

## Quickstart (5 minutes)

### 1. Clone
```bash
git clone https://github.com/karthik-gct/Mark3.git
cd Mark3
```

### 2. Run setup
```bash
bash setup.sh
```

The script will:
- Prompt for your Jira URL, email, and API token
- Prompt for your Anthropic API key
- Prompt for the path to element35-mcp (optional)
- Write `.env` with your credentials
- Generate `.claude/settings.json` from the template
- Validate your Jira connection live

### 3. Generate a Jira API token
Go to: `https://id.atlassian.com/manage-profile/security/api-tokens`  
Click **Create API token** → copy the token → paste it when `setup.sh` asks.

### 4. Fill in your project's stack
Open `ArchitectureDesign.md` and fill in:
- `project_name`, `jira_project_key`, `github_repo`
- Tech stack (backend, frontend, infra)
- Design principles and module boundaries

### 5. Open in Claude Code
```bash
claude   # or open the project in the Claude Code desktop app
```

### 6. Run your first agent
Create a CONCEPT ticket in Jira, then:
```
/prod-agent YOUR-ISSUE-KEY
```

## Directory Structure

```
Mark3/
├── SETUP.md              ← you are here
├── CLAUDE.md             ← harness entry point (read by Claude Code)
├── Agents.md             ← loop limits, model keys, eval thresholds
├── ArchitectureDesign.md ← YOUR project's tech stack (fill this in)
├── models.config.yaml    ← model routing (cloud-direct → STARK-switchable)
├── setup.sh              ← interactive setup script
├── .env.example          ← template for .env
├── .env                  ← your credentials (gitignored — created by setup.sh)
│
├── .claude/
│   ├── settings.template.json  ← template (committed)
│   ├── settings.json           ← generated by setup.sh (committed, no secrets)
│   └── commands/               ← slash commands for each agent
│
├── agents/               ← agent system prompts + eval rubrics + templates
├── context/              ← context graph interface contract
├── integrations/         ← Jira and GitHub configs
├── workflows/            ← PDLC, SDLC, feedback loop definitions
└── artifacts/            ← runtime output (gitignored — created during runs)
```

## Slash Commands

| Command | What it does |
|---|---|
| `/prod-agent <jira-key>` | CONCEPT → EPIC → STORYs → SPECS (max 3 iterations) |
| `/design-agent <specs-path>` | SPECS → DESIGN (grounded in CODE_GRAPH) |
| `/code-agent <specs-path> <design-path>` | DESIGN → code + unit tests (max 5 iterations) |
| `/quality-agent <story-key> <branch>` | Branch → QA report (max 3 iterations) |

## Switching to STARK Router

When you want to route LLM calls through your local DGX/STARK instead of the cloud directly:

1. In `models.config.yaml`, change:
   ```yaml
   routing_backend: "direct"
   ```
   to:
   ```yaml
   routing_backend: "stark"
   ```

2. Ensure STARK is running:
   ```bash
   cd $STARK_ROOT && python3 -m stark.api.server
   ```

3. Add the Mark3 task types to `~/.stark/config.yaml` routing_rules (see `models.config.yaml` comments at the bottom).

## Troubleshooting

| Problem | Fix |
|---|---|
| Jira auth 401 | Regenerate API token at `id.atlassian.com`. Re-run `setup.sh`. |
| element35 MCP fails to start | Run `cd $ELEMENT35_MCP_ROOT && npm install && npm run bootstrap-dbs` |
| No issues found in Jira | Create a ticket first, then run `/prod-agent <key>` |
| Agent loop exceeds MAX_LOOPS | Edit `Agents.md` to increase the limit, or review the escalation file in `artifacts/specs/` |
| `settings.json` has wrong paths | Re-run `setup.sh` — it regenerates `settings.json` from the template |
